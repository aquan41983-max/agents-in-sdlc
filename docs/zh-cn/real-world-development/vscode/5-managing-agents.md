使用 GitHub Copilot 智能体模式时，Copilot 会自主探索代码库、提出变更、编辑文件并运行命令。由于工作会实时发生在你的机器上，VS Code 中的 Copilot Chat 会显示每次工具调用和文件编辑。你可以内联审查差异、逐项接受或拒绝变更，并通过后续提示引导对话，无需离开编辑器。

本练习将介绍如何：

- 实时监控无障碍智能体的工作；
- 审查并接受建议的文件编辑；
- 在会话进行时引导智能体添加浅色模式切换。

## 场景

[练习 4][previous-lesson] 中使用的无障碍自定义智能体正在实现高对比度模式。工作进行时，设计团队提出了新要求：为觉得默认主题太暗的用户添加浅色模式。你将引导现有会话扩展工作，而不是从头开始新会话。

## 监控 Copilot 的进度

Copilot Chat 会显示智能体的每个步骤，包括探索的文件、运行的命令和提出的编辑。每项文件编辑都会以内联差异和 **Keep** / **Undo** 控件显示：

1. 返回练习 4 的 Copilot Chat 视图。
2. 智能体工作时，滚动聊天内容查看工具调用，包括文件读取、编辑和请求运行的终端命令。
3. 看到文件编辑差异时：
   - 选择 **Keep** 接受变更；
   - 选择 **Undo** 撤销变更，让智能体重新尝试。
4. 也可以打开聊天顶部的 **Files changed** 指示器，查看该会话中智能体修改的全部文件。

> [!NOTE]
> 如果工具调用请求权限（例如运行终端命令），智能体会暂停并显示 **Allow** 提示。只批准你认可的命令。

5. 等待智能体完成高对比度模式，随后会显示变更摘要。

## 引导智能体添加浅色模式

高对比度模式完成后，在同一对话中要求添加浅色模式。由于继续使用同一会话，智能体会保留之前的上下文，包括修改的组件、样式方案和本地存储模式。

1. 在 Copilot Chat 输入框中发送以下后续提示：

    ```plaintext
    做得不错！现在在高对比度切换旁边添加浅色模式切换。浅色模式应采用相同模式，通过本地存储保存设置，并在 UI 的同一区域提供入口。用户应能分别启用高对比度和浅色模式。
    ```

2. 智能体会检查已有变更并继续添加浅色模式。
3. 按照之前的方式审查每项新编辑，使用 **Keep** 或 **Undo**。
4. 如果智能体的方向不合适（例如尝试以不喜欢的方式重构切换 UI），可以选择聊天输入框旁的 **Stop** 按钮停止任务，再发送澄清提示。

> [!TIP]
> 使用后续提示引导正在进行的会话，比从头开始更快。例如，可以要求简化 CSS 并使用 CSS 变量、将浅色模式整合到现有设置面板，或为两种切换添加键盘快捷键。

## 审查工作集

提交前快速审查智能体修改的所有内容：

1. 在 VS Code 中打开 **Source Control** 视图。
2. 检查变更文件列表，其中应包含 Astro 组件、样式和相关测试。
3. 打开几个变更文件，审查差异。确认包含无障碍智能体要求的模式，例如 ARIA 属性、键盘导航、语义化 HTML 和本地存储。
4. 确认变更后，在 Source Control 面板中暂存并提交。下一课将发布这些变更。

## 总结和下一步

你使用 Copilot Chat 智能体模式监控并引导正在进行的会话：检查文件编辑、接受或拒绝变更，并在保留上下文的情况下发送后续提示扩展工作。

本课中，你了解了实时监控智能体工作、接受或拒绝单项文件编辑，以及在会话进行时通过后续提示引导工作。

下一课会将无障碍功能作为 PR 发布，并审查本实验中本地自定义智能体创建的变更。
