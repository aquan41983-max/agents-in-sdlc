GitHub Copilot を agent mode で使うと、コードベースを調査し、変更を提案してファイルを編集し、コマンドを実行します。VS Code の Copilot Chat では、ツールの呼び出しやファイルの編集をリアルタイムで確認できます。差分をインラインでレビューし、個々の変更を承認または却下し、フォローアップのプロンプトで会話を調整できます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集を確認して承認します。
- セッションの途中でエージェントに指示を追加し、ハイ コントラストに加えてライト モードの切り替えも追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタム エージェントは、ハイ コントラスト モードを実装しています。作業中にデザイン チームから、既定のテーマが暗すぎると感じるユーザー向けにライト モードも追加してほしいと依頼がありました。新しい会話を始める代わりに、現在のセッションを調整して作業を拡張します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが調べているファイル、実行するコマンド、提案する編集が表示されます。ファイル編集は差分と **Keep** / **Undo** の操作とともに Chat 内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中、Chat をスクロールしてツールの呼び出しを確認します。ファイルの読み取りと編集、実行を求めるターミナル コマンドが表示されます。
3. ファイル編集の差分が表示されたら、次のいずれかを選択します。
   - **Keep**: 変更を承認します。
   - **Undo**: 変更を元に戻し、エージェントに再度作業させます。
4. Chat 上部の **Files changed** を開くと、セッション中にエージェントが変更した作業ファイル全体を確認できます。

> [!NOTE]
> ターミナル コマンドの実行などでツールの許可を求められた場合、エージェントは一時停止して **Allow** を表示します。許可するコマンドは、内容を確認して判断してください。

5. エージェントがハイ コントラスト モードを実装し終えるまで待ちます。最後に変更の概要が表示されます。

## ライト モードを追加するようエージェントに指示する

ハイ コントラスト モードができたら、同じ会話でライト モードの切り替えを追加します。同じ Chat セッションを続けるため、エージェントは変更済みのコンポーネント、スタイルの方針、local storage を使った設定の保存方法を把握しています。

1. Copilot Chat の入力欄に次のフォローアップ プロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントは前の作業を確認し、ライト モードを追加する提案をします。
3. 追加される編集を確認し、各差分で **Keep** または **Undo** を選択します。
4. エージェントが意図しない方針 (たとえば、好みと異なるトグル UI のリファクタリング) に進んだら、Chat 入力欄の横にある **Stop** で停止し、明確なフォローアップを送ります。

> [!TIP]
> 作業中のセッションを調整すると、最初からやり直すより短時間で進められます。「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使う」「3つ目のトグルを追加せず、既存の設定パネルにライト モードを統合する」「両方のトグルにキーボード ショートカットも追加する」のような指示を送れます。

## 作業ファイルをレビューする

コミットする前に、エージェントが変更したファイルを確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタム エージェントが指示したアクセシビリティのパターン (ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保存) を確認します。
4. 問題がなければ **Source Control** パネルでステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat agent mode で作業中のセッションを監視して調整し、ファイル編集を確認して承認または却下し、コンテキストを保ったままフォローアップ プロンプトで作業を拡張しました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を承認または却下しました。
- フォローアップ プロンプトで進行中のセッションを調整しました。

次のレッスンでは、アクセシビリティの作業をプルリクエストとして公開し、このラボでローカルのカスタム エージェントが生成した変更をレビューします。
